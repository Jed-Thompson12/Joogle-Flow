# Security Policy

## Supported Versions

Joogle Flow is actively maintained, and security updates are provided for supported versions.

| Version | Supported |
| ------- | --------- |
| 5.1.x   | ✅ Yes     |
| 5.0.x   | ❌ No      |
| 4.0.x   | ✅ Yes     |
| < 4.0   | ❌ No      |

Security fixes may be released as patch versions when vulnerabilities are discovered.

> **Note:** Users are encouraged to keep Joogle Flow updated to the latest supported release.

## Reporting a Vulnerability

If you discover a security vulnerability in Joogle Flow, please report it responsibly rather than publicly opening an issue.

### How to Report

Please report vulnerabilities through **GitHub's private vulnerability reporting feature** for this repository.

When submitting a report, please include:

* A clear description of the vulnerability
* The affected version(s)
* Steps to reproduce the issue
* The potential security impact
* Any relevant logs, screenshots, or proof-of-concept code
* A suggested fix, if you have one

Please avoid including sensitive information that is not necessary to reproduce the vulnerability.

### What Happens Next

We aim to:

1. **Acknowledge your report within 7 days.**
2. Investigate and validate the reported vulnerability.
3. Determine which versions are affected.
4. Develop and test a security fix where appropriate.
5. Release the fix as soon as reasonably possible.
6. Credit the reporter if they wish to be acknowledged.

### Accepted Vulnerabilities

If a vulnerability is confirmed, we will work to resolve it and may publish a security advisory containing relevant information once a fix is available.

The exact timeline for a fix depends on the severity and complexity of the vulnerability.

### Declined Reports

A report may be declined if:

* The issue is not a security vulnerability.
* The issue cannot be reproduced.
* The report describes expected behaviour.
* The vulnerability only affects unsupported versions.
* The reported behaviour has negligible security impact.

If a report is declined, we will provide an explanation where practical.

### Responsible Disclosure

Please do not publicly disclose a vulnerability until we have had a reasonable opportunity to investigate and address it.

We appreciate responsible security research and the time taken to help make Joogle Flow safer for everyone.

## Security Updates

Security updates will be announced through the project's GitHub repository and, where appropriate, GitHub Security Advisories.

Users should regularly update Joogle Flow to ensure they receive the latest security fixes.
